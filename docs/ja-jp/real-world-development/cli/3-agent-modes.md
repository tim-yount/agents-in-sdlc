最初に小さな機能を追加しました。より大きな変更には、さらにしっかりしたプロセスが必要です。GitHub Copilot CLI は組織の既存の開発フローに沿って動作し、適切な方法で適切なものを構築できるようにします。このレッスンは、エージェント主導の一般的な開発プロセスを学ぶ一連のレッスンの最初です。イシューから新機能を作成し、コードの妥当性と機能の動作を確認して、プロジェクトへのマージまで進めます。

> [!NOTE]
> 機能の作業が続く間は、同じ会話とブランチを使います。通常、ファイルの種類ごとに異なるブランチや PR を作成しますが、ここでは主な概念に集中できるよう手順を簡略化しています。

このレッスンでは、次のことを行います。

- GitHub イシューから Copilot の会話を開始します。
- Plan モードで要件を定義します。
- Autopilot モードで機能を実装します。
- コードをレビューします。
- 転送されたブラウザーで機能を手動で検証します。

機能の開発を続けながら、リポジトリの指示を更新し、既存の `quality-checks` スキルをカスタマイズし、MCP による検証を追加し、QA エージェントを作成して、機能の PR を開きます。

## シナリオ

Tailspin Toys のカタログが増え、訪問者はカテゴリや出版社でゲームを絞り込む必要があります。バックログのイシューには機能の概要がありますが、カテゴリを組み合わせる方法など、コーディングの前に合意が必要な詳細があります。Plan モードで方針を決め、その後、範囲を限定した実装を Autopilot に許可します。

## 背景

AI コーディングエージェントを開発フローに導入しても、基本は変わりません。むしろ、より重要になります。多くの開発者は、次のような手順で作業します。

1. 実装する内容を説明したイシューから開始します。
2. 構築する機能の計画を立てます。
3. コードを作成してレビューします。
4. テストを実行してコードを検証します。
5. 新機能を手動で検証します。
6. プルリクエスト (PR) を作成します。
7. コードレビューと継続的インテグレーションが成功したら、コードをマージします。

> [!NOTE]
> 具体的な手順はチームや組織によって異なりますが、多くの場合は上記の流れに沿っています。

この標準的な方法を守ることで、AI が生成したコードが要件を満たし、手作業で作成したコードと同じレビュー手順を経るようにします。

## 会話モード

**会話モード**は、エージェントがどれだけ自律的に作業するかを制御します。<kbd>Shift</kbd>+<kbd>Tab</kbd> を押すと、モードを切り替えられます。

- **Interactive**: ユーザーとエージェントが共同で作業します。エージェントは変更を提案し、次に進む前にユーザーの入力を待ちます。
- **Plan**: エージェントが最初に計画を作成します。プロジェクトファイルの編集はできません。
- **Autopilot**: エージェントがコードを書き、テストを実行し、タスクが完了するまで自律的に反復します。

まず Plan モードで計画をレビューし、その後 Autopilot で実装します。

## イシューから始める

フィルター機能の作業を始める前に、Codespace とリポジトリを準備します。

1. Codespace に戻ります。停止している場合は再起動します。
2. 星評価の PR がマージ済みであることを確認します。
3. ターミナルが開いていない場合は、<kbd>Control</kbd>+<kbd>`</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>`</kbd> (Windows/Linux) を押して開きます。
4. `main` を更新し、フィルター作業用のブランチを作成します。

   ```bash
   git checkout main
   git pull --ff-only
   git checkout -b game-filters-cli
   ```

5. Copilot CLI を起動します。

   ```bash
   copilot --yolo
   ```

6. <kbd>Tab</kbd> を 2 回押して **Issues** タブを開きます。
7. <kbd>A</kbd> を押してすべてのイシューを表示します。
8. 矢印キーを使って **Allow users to filter games by category and publisher** というタイトルのイシューを選択します。
9. <kbd>C</kbd> を押してイシューをプロンプトに追加し、**Session** タブに戻ります。

プロンプトの先頭に `#7`（または同様の番号）が表示されます。`#` を使うと、GitHub 上のイシューやプルリクエスト (PR) をコンテキストに追加できます。

## フィルター機能を計画する

計画を立てると、Copilot に任せる前に機能の実装方法やタスクの進め方を決められます。複雑な作業では、事前に時間をかけて計画することをお勧めします。Plan モードに切り替え、Copilot に計画を作成してもらいましょう。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Plan モードに切り替えます。プロンプトの下に **Plan** と表示されていることを確認します。
2. 前の手順で追加したイシューの後に、次のプロンプトを入力します。

   ```plaintext
   Create a plan for implementing this feature.
   ```

Copilot はプロジェクトを調べ、適切な方法を検討して計画を作成します。

3. フィルター機能の動作について質問された場合は、希望に沿って回答します。正解は 1 つではありません。
4. 計画が完成したら、<kbd>Control</kbd>+<kbd>E</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>E</kbd> (Windows/Linux) を押して計画を展開します。
5. 計画を上下にスクロールしてレビューします。
6. 決定した内容と合わない部分があれば、変更を依頼します。

## Autopilot を承認する

計画を作成してレビューしたら、実装に進みます。Autopilot を使って Copilot に作業を任せます。

Autopilot を使うと、タスクが完了したと判断するまで Copilot が問題に取り組みます。

1. **Accept plan and build on autopilot (recommended)**、またはインストールされているバージョンで同様の名前が付いたオプションを選択します。
2. プロンプトの下に **Autopilot** と表示されていることを確認します。
3. Copilot が計画に沿って作業し、コードを生成してテストを実行する様子を確認します。

> [!NOTE]
> 承認すると実装がすぐに始まることがあります。事前に計画を確認してください。依存関係が不足している、またはポートが競合していると報告された場合は、チェック完了と判断する前に環境の問題を解決してください。

## 実装をレビューして検証する

コードが生成されたら、ほかのコードと同じように、マージする前にレビューします。コードをレビューし、サイトを実行して問題がないことを確認します。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Interactive モードに切り替えます。モード表示が **Plan** または **Autopilot** ではないことを確認します。
2. `/diff` を入力し、フィルター機能とテストを確認します。
3. 結果をイシューと計画中に決めた内容と比較します。
4. コードのレビューが終わったら <kbd>Esc</kbd> を押して差分ビューを閉じます。
5. プロジェクトのチェック結果を確認し、失敗があれば Copilot に解決を依頼します。

## 新機能を確認する

コードが問題なく見えても、実際に動くか確認しましょう。前と同じようにアプリを起動し、Codespaces で転送されたポートからサイトを開きます。

1. Copilot に次のように依頼してアプリを起動します。

   ```plaintext
   Start the app so I can try the filtering feature in my browser. Tell me the URL and leave the server running.
   ```

2. Codespaces からポート `4321` が利用可能と通知されたら、**Open in Browser** を選択します。
3. 計画で決めたカテゴリと出版社のフィルター、およびその組み合わせを試します。
4. リセット動作と結果が空の場合の動作が、イシューと決定内容に合っていることを確認します。
5. Codespace に戻り、起動した開発サーバーを停止するよう Copilot に依頼します。

## まとめと次のステップ

さまざまな会話モードを使って機能を作成し、レビューしました。このレッスンでは、次のことを行いました。

- GitHub イシューから Copilot の会話を開始しました。
- Plan モードで要件を定義しました。
- Autopilot モードで新機能を実装しました。
- コードをレビューしました。
- 転送されたブラウザーで機能を手動で検証しました。
