GitHub Copilot をエージェントモードにすると、コードベースを調べ、変更を提案し、ファイルを編集し、コマンドを実行します。VS Code の Copilot Chat では、作業中のツール呼び出しやファイル編集をリアルタイムで確認できます。差分をインラインでレビューし、個々の変更を適用または取り消し、エディターを離れずに追加のプロンプトを送って作業を改善したり広げたりできます。

この演習では、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして適用します。
- セッションの途中でエージェントを誘導し、ハイコントラストモードに加えてライトモードも追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティカスタムエージェントが、ハイコントラストモードを実装しています。作業中にデザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードも切り替えられるようにします。新しい会話を始めるのではなく、既存のセッションを誘導して機能を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが実行する各手順が表示されます。調べたファイル、実行したコマンド、提案した編集を確認できます。ファイル編集は差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. 演習 4 で使用した Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツールの呼び出しを確認します。ファイルの読み取りや編集、実行を求めるターミナルコマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がチャット内に表示されます。
    - 変更を適用するには **Keep** を選択します。
    - 変更を元に戻し、別の方法を試すには **Undo** を選択します。
4. チャット上部の **Files changed** 表示を開くと、セッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ターミナルコマンドの実行など、ツールの許可を求められた場合、エージェントは一時停止して **Allow** を表示します。実行してもよいコマンドだけを許可してください。

5. エージェントがハイコントラストモードの実装を完了するまで待ちます。最後に、行った変更をまとめたメッセージが表示されます。

## ライトモードを追加するようエージェントを誘導する

ハイコントラストモードができたら、同じ会話でライトモードの切り替えも追加します。同じチャットセッションを続けるため、エージェントは前の作業で扱ったコンポーネント、スタイルの方法、ローカルストレージの使い方などのコンテキストを保持しています。

1. Copilot Chat の入力欄に次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントはすでに行った変更を確認し、ライトモードの追加を提案します。
3. ハイコントラストモードのときと同じように、新しい編集を確認し、差分ごとに **Keep** または **Undo** を選択します。
4. エージェントの方針が希望と異なる場合（たとえば、好みでない方法でトグル UI をリファクタリングしようとした場合）は、チャット入力欄の横にある **Stop** ボタンで停止し、追加メッセージで意図を説明します。

> [!TIP]
> 作業中のセッションを誘導すると、最初からやり直すよりも速く進められます。追加プロンプトで「CSS を簡潔にし、セレクターの重複ではなく CSS 変数を使う」のような調整、「3 つ目のトグルは追加せず、既存の設定パネルにライトモードを統合する」のような軌道修正、「両方のトグルにキーボードショートカットも追加する」のような範囲の拡張を依頼できます。

## 変更されたファイルをレビューする

変更をコミットする前に、エージェントが変更したファイルを確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されています。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントが指示したアクセシビリティパターン（ARIA 属性、キーボード操作、セマンティック HTML、ローカルストレージによる設定保持など）が反映されていることを確認します。
4. 問題がなければ **Source Control** パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードを使い、作業中のセッションを監視して誘導しました。ファイルの編集を確認し、変更を適用または取り消し、コンテキストを失わずに追加の依頼を送って作業を拡張しました。

このレッスンでは、次のことを確認しました。

- エージェントの作業をリアルタイムで監視する。
- 個々のファイル編集を適用または拒否する。
- 追加プロンプトで作業中のセッションを誘導する。
